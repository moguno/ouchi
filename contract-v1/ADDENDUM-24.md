# ADDENDUM-24: 関係のデータ構造の再設計（関係名の分離）

関係（relations）のモデルを作り替える。色と方向ラベルを関係の各行から
分離し、「関係名」という定義エンティティに寄せる。

## 新モデル

### 関係名（relation name）

- 名前（一意、自然キー）
- 色
- 始点の名前（その関係の始点側デバイスに付けるラベル。任意）
- 終点の名前（終点側デバイスに付けるラベル。任意）

### 関係（relation）

- 関係名への参照
- 始点デバイス
- 終点デバイス

関係の行はこの3つだけを持つ。色・ラベルは関係名から引く。

### ルール

- 同じ始点→終点ペアに、異なる関係名の関係を複数持てる。
  一意性は（関係名、始点、終点）の組で担保し、同じ組の重複は拒否する。
- 使用中（関係が1件以上ある）の関係名は削除できない（409）。
  未使用なら削除できる。ネットワーク削除の既存方針と揃える。
- ポータルのラベル表示：関係 A→B（関係名 N）について、A 側に
  N の始点の名前、B 側に N の終点の名前を表示する。名前が空の場合は
  関係名そのもので代替する。
- 関係は独立エンティティのまま（デバイスへの埋め込みはしない）。

## 移行（マイグレーター連鎖の1段として実装する）

移行は「1段ずつ進める変換の連鎖」で担う方針が決まっている。
今回はその最初の本格的な段として、次を実装する。

### DB

- 起動時移行の次番号（004）で新モデルへ移す：
  - 関係名テーブルを新設する。
  - 既存の関係をタグでグルーピングし、関係名を自動生成する。
    色と fromLabel/toLabel は、そのタグの最初の関係から採用する。
  - 関係テーブルを新モデルに再構成し、データを保持する。
- 旧スキーマ DB で移行を検証するテストを必須とする（プロパティ
  移行の前例と同様）。既存データ（デバイス等）は壊さない。

### YAML

- 形式に `relationNames:` セクションを追加し、関係は関係名を
  名前で参照する形に変える。形式バージョンを上げる。
- 旧形式（関係の行に tag/color/fromLabel/toLabel を持つエクスポート）
  を取り込めるよう、1段変換を用意する：タグでグルーピングして
  関係名を生成し、新形式に変換してから取り込む。変換は DB 移行と
  同じ規則（色とラベルはタグの最初の関係から）で揃える。
- デモ用サンプル YAML（public/ouchi-ledger.sample.yaml）は新形式に
  更新する。

## REST API

- 関係名の CRUD を追加する（GET 一覧・単体、POST、PUT、DELETE）。
  一覧の各要素には、その関係名を使っている関係の件数を含める。
- 関係の CRUD は新モデルに合わせる：入力は関係名（名前で指定）・
  始点デバイス・終点デバイス。表現には関係名の色・始点の名前・
  終点の名前を解決して含める（利用側が組み立てなくて済む形）。
- 旧 `PUT /api/relations/tags/:tag/color` は廃止し、色変更は
  関係名の更新に一本化する。
- `GET /api/portal` には関係名の一覧と、色・ラベル解決済みの関係を
  含める。
- 検証は既存の共有検証モジュールに寄せる：関係名は非空・一意、
  色は既存の色形式、始点≠終点、関係名の存在、組の重複拒否。

## MCP

- 関係名の読み取り・CRUD ツールを追加する。
- 関係の作成・更新ツールは関係名を指定する形に変える。
- 地図テキストと近傍表示では、関係名と方向ラベル（始点の名前／
  終点の名前）を定義側から表示する。

## GUI

### 関係タブ

- 関係名の一覧を置く：名前、色チップ、始点の名前、終点の名前、
  **使用件数のバッジ**、編集・削除導線。使用中は削除できない旨が
  件数から分かるようにする。
- 関係名の追加・編集ダイアログ（名前、色、始点の名前、終点の名前）。
- 関係の一覧は現行を踏襲し、タグチップは関係名＋その色で表示する。
- 関係の追加・編集ダイアログは、関係名の選択＋始点・終点デバイスの
  選択にする。デバイス編集内の関係編集とコンポーネント共用は維持。
- 旧「タグ単位の色」セクションは関係名一覧に置き換える。

### ポータル

- 接続線の色は関係名の色から取る。ラベル表示は上記ルールに従う
  （空なら関係名で代替）。接続点の配置ルール（ADDENDUM-12/13）は
  変更しない。

## 検収条件

- 旧スキーマ DB（タグ付き関係5件を含む台帳）が起動時移行で
  新モデルに変換され、関係名2件（ホストOS／バックアップ先相当）と
  関係5件が保持される。
- 旧形式 YAML のインポートが1段変換を経て正しく取り込まれ、
  新形式 YAML で往復する。
- API：関係名 CRUD（使用中削除が 409）、関係 CRUD（組の重複拒否、
  複数関係名の同居）、portal 表現への解決済み色・ラベルの含有。
- MCP：地図テキストに関係名と方向ラベルが出る。関係名ツールが動く。
- GUI：関係タブで関係名の CRUD と使用件数バッジ、関係の編集が
  動く。ポータルで線の色とラベルが新モデルどおり描画される。
- 既存テスト全件パス＋上記の新規テスト。
- README と contract-v1/schema.sql を新モデルに合わせて更新する。
- 結果を 報告書.md に追記する。
