# ADDENDUM-22: デバイス／サービスのプロパティ（任意キーバリュー）

v1 本体と ADDENDUM-20（MCP）への追加。デバイスとサービスが、任意の
キー・バリューからなる `properties` マップを持てるようにする。

## 背景と用途

- 用途は、Vault のキー（パス）のような参照情報、SOPS で暗号化済みの文字列、
  AI に対する注釈、メモ（例：「HDD smart怪しい」）を、デバイス／サービスに
  ぶら下げておくこと。
- MCP と API で「基本情報として」取得できることが重要。AI が保守のときに
  地図と一緒にプロパティを読めるのが価値の中心。

## 設計の要点（変更不可）

- プロパティはデバイス／サービス本体の一部である。独立した属性リソースや
  属性専用エンドポイントは作らない。内部の持ち方（JSON 列か裏側の別
  テーブルか）は実装の自由とする。
- キーは自由文字列で、列挙や固定のキー集合は作らない。用途はキー名の
  慣習で表す。
- 更新の意味論：
  - 更新ペイロードに `properties` が**含まれれば全量置換**する。
  - `properties` が**欠けている場合は既存のプロパティを保持**する。
    プロパティを知らないクライアントからの更新で消えてはならない。
- 値は SQLite に平文で保存される。平文の秘密を入れる用途ではない。
  管理画面のプロパティ編集欄と README に「平文の秘密情報は入力しない
  こと。必要な場合は SOPS などで暗号化した文字列を入れること」と
  明記する。

## 実装範囲

### 台帳と検証

- devices と services に `properties`（キー文字列 → 値文字列のマップ）を
  持たせる。既存 DB のデータを壊さないこと。移行はエクスポート→
  インポートが原則だが、petname の前例（起動時の ALTER 1回）でもよい。
- 検証は既存の共有検証モジュールに寄せる：
  - キー：前後空白を除去し、非空、最大128文字。
  - 値：文字列、最大64KiB。
  - YAML インポートで同一エンティティ内に同じキーが重複したら拒否する。

### REST API

- デバイス／サービスの表現（単体取得、一覧、`GET /api/portal`）に
  `properties` を含める。未設定なら空マップ。
- 作成・更新ペイロードで `properties` を受け付ける。意味論は上記の通り
  （あれば全量置換、欠ければ保持）。

### YAML エクスポート／インポート

- 各デバイス／サービスに `properties:` マップを持たせ、往復で保持する。
- `properties` の無い旧エクスポートもインポートできること（空として扱う）。
- エクスポートは全プロパティを含む。SOPS 暗号文のような値も除外しない。

### MCP

- 読み取り系ツール（get_network_map の地図テキスト、get_device_neighborhood、
  search_devices、search_services）の出力にプロパティを含める。
- デバイス／サービスの更新系ツールが `properties` を運べるようにする
  （意味論は REST と同じ）。キー単位の set/delete 補助ツールは任意。

### GUI

- 管理画面のデバイス／サービスの設定ペインで、そのエンティティの
  プロパティを全数ロードし、行の追加・変更・削除を編集できる。
  保存時にマップ全体を一括で送る（全量置換と一致させる）。
- プロパティ編集欄に平文の秘密を入れない旨の注意書きを置く。
- ポータル側は詳細表示でプロパティが見える程度でよい。

## 検収条件

- API でデバイスとサービスにプロパティを付けて読み書きでき、更新時の
  「欠ければ保持」が効いている（プロパティなしの更新で消えない）。
- MCP の地図テキストと検索結果にプロパティが含まれ、更新ツールで
  書き換えられる。
- エクスポート→インポートでプロパティが保持される。properties の無い
  旧 YAML もインポートできる。
- 空キー、上限超の値、YAML のキー重複が拒否される。
- デバイス／サービスを削除すると、そのプロパティも消える。
- 既存テストが全件パスし、新規テストが上記を覆う。
- README にプロパティの説明と平文の秘密を入れない注意を追記する。
- 結果を 報告書.md に追記する。

## 範囲外

- SOPS 暗号文ファイル自体の保持・配布（別ブリーフ）。
- プロパティの暗号化（ouchi は復号も暗号化もしない）。
- キー単位の専用 REST エンドポイント。
