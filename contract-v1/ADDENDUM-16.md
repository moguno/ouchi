# 追加ブリーフ 16：アイコン検索ピッカー＋汎用アイコン同梱（2026-11-21、カイル）

## 内容

サービスのアイコンを、管理画面で **dashboard-icons を文字列検索して候補から選んで適用**できるインターフェースを追加する。あわせて、**ネットに繋げない環境用に汎用アイコン集をアプリへ同梱**する。ユーザー指示。

## 仕様

### 1. 検索ピッカー（管理画面のサービス編集）

- 現在のプルダウンを、検索つきピッカーに置き換える（または拡張する）。
- 検索ボックスに文字列を入れると、dashboard-icons の候補が絞り込まれ、**アイコンのプレビュー＋名前**が候補として並ぶ。クリックで選択し、保存でサービスに適用される。
- 候補は2グループに分けて出す：
  - **汎用アイコン**（同梱分。オフラインでも常に選択可）
  - **dashboard-icons**（下記の索引で検索。プレビューは CDN 取得でもよい）

### 2. dashboard-icons の索引と取得

- 検索に使う索引（スラッグ＋表示名の一覧）は**アプリに同梱**し、検索自体はオフラインでも動くこと。索引の作り方（dashboard-icons のメタデータから生成する等）とサイズを報告書に明記すること。取得元は jsDelivr（cdn.jsdelivr.net の homarr-labs/dashboard-icons）。
- 適用した dashboard-icons アイコンは、**適用時にアプリ側へ取り込んでローカル保持**する（データボリューム等）。ポータル表示時に CDN へ依存しないこと。再取得可能なキャッシュとして扱い、保持形式・保存先を報告書に明記すること。

### 3. 汎用アイコン集の同梱

- 既存のプリセット9種（gitea／gatus／proxmox／omv／server／database／monitor／container／globe）は残す。
- それとは別に、汎用アイコンのセットを同梱して候補に出す（例：メール、カメラ、プリンタ、フォルダ、クラウド、シールド、カレンダー、チャート等の一般概念）。ライセンスがクリーンなもの（自作マークの拡張、または MIT／ISC 等の OSS アイコン）を使い、出典とライセンスを報告書に明記すること。件数の目安は 15〜30 件程度。

### 4. データとエクスポート/インポート

- サービスのアイコン参照は、プリセット／汎用／dashboard-icons の3種を区別できる形にする。
- YAML エクスポート/インポートでアイコン参照が往復すること。dashboard-icons のアイコンはスラッグ参照を正とし、インポート先でローカル保持分が無い場合は「オンラインなら再取得、オフラインなら汎用アイコンで代替表示」のように壊れない扱いにし、その仕様を報告書に明記すること。

### 5. デモへの影響

- GitHub Pages デモ（読み取り専用）は管理画面を持たないのでピッカーは不要。ただしサンプルデータのアイコン表示が従来どおり同梱分だけで描画できることを維持すること。

## 検収

- 既存テストが全件成功すること。検索の絞り込み、適用、エクスポート/インポート往復のテストを追加すること。
- 索引サイズ、アイコンの保持形式・保存先、オフライン時の挙動（検索可否・代替表示）を報告書に明記すること。
