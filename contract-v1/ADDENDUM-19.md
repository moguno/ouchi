# 追加ブリーフ 19（改訂版）：同じタグ＝同じ色を、関係テーブルの色＋検証で強制（2026-11-21、カイル）

## 内容

関係（relation）の色は **関係テーブルに持ったまま**とし、「同じタグ＝同じ色」を共有バリデーションで強制する。ユーザー再検討による決定（タグ定義の別テーブル化はしない）。対象は製品仕様（台帳・API・GUI・YAML）全体。

※ 本書は旧版 ADDENDUM-19（tags テーブル新設案）を置き換える。旧版の実行は途中で停止されたため、作業ツリーに旧版の未完了な変更（tags テーブル前提の変更）が残っている可能性がある。**まずそれを確認し、tags テーブル前提の変更だけを外科的に取り消すこと**（他の追加ブリーフ 14〜18、補足 5〜9 の変更は保持する）。取り消した内容は報告書に明記し、テストが通る状態に戻してから、本書の実装に入ること。

## 仕様

1. **データ構造は変えない**：関係は従来どおり `tag` と `color` を持つ。tags テーブルは作らない。YAML 形式も変えない（関係に色が付いたまま）。
2. **バリデーション（共有バリデーション層）**：同じ tag を持つ関係は、すべて同じ color でなければならない。既存タグと違う色での関係の作成・更新はバリデーションエラーにする。YAML インポートでも、タグ内で色が食い違うデータは検証エラーとして弾くこと。
3. **色の変更はタグ単位**：あるタグの色を変える操作は、そのタグを持つ全関係の color をトランザクション内で一括更新する。
4. **管理 UI の関係エディタ**：
   - 既存タグを選んだ場合、色はそのタグの既定色に固定され、個別には変更できない（色を変える場合は「タグの色を変更」として全件反映になることを UI 上で明示する）。
   - 新規タグの場合のみ、色を自由に選べる。
   - タグ入力は既存タグの候補提示（サジェスト）があると望ましい。
5. **既存データの整合**：API モード用シード等、既存データに同タグ異色があれば、最初に現れる色に揃えて報告書に明記すること（デモサンプルは補足 9 で統一済みの想定だが、二重に確認してよい）。

## 背景メモ

- 従来のモデルでは色は関係ごとの「程度」の表現だったが、本決定により色はタグの識別色として扱う。程度の違いを表したい場合はタグを分ける運用になる。
- 将来タグに色以外の属性（説明、既定ラベル等）を持たせることになったら、その時点でタグテーブルへの分離を再検討する（移行はエクスポート→インポートで吸収できる）。
