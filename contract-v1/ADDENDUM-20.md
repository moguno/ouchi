# 追加ブリーフ 20：MCP ブロック（AI用のネットワーク地図）（2026-11-22、カイル）

## 内容

ouchi.local の台帳を AI エージェントから読み書きできる **MCP サーバー**を実装する。コンセプト（確定稿）：「AI用のネットワーク地図」— (1) 設定を AI に任せる、(2) デバイス保守時にネットワーク構成を構造テキストで AI に教える。

## 前提

- 台帳の REST API（v1）が完成していること。MCP はその上に乗る薄い層とし、**検証ルールは REST と共通化**する（MCP 独自の検証を持たない）。
- 言語・リポジトリはバックエンドと同じ（TypeScript、同リポジトリ、別プロセスとして起動可能にする）。

## 仕様

### 接続

- トランスポートは **HTTP**（Streamable HTTP）。リモートの AI エージェントからも接続できる形にする。
- 認証は今回なし。ただし前提は **LAN 内利用のみ・WAN に公開しない**こと。この前提を README 等のドキュメントに明記すること。

### 読み取りツール

- **地図テキスト生成**：ネットワーク → デバイス → サービスの階層と、関係（方向ラベル・タグ・色を含む）をたどった構造テキストを返す。保守対象デバイスを指定すると、そのデバイスを起点に関係をトラバースした周辺構成も含める。
- デバイス／サービスの検索（名前・ホスト名・タグ等）。
- サービスの URL 解決（台帳の組み立て規則で完全な URL を返す）。

### 書き込みツール

- ネットワーク／デバイス／サービス／関係の CRUD。すべて REST と共通の検証を通すこと（例：同じタグ＝同じ色、サービスカテゴリ擬似デバイスの規則、自然キーの整合性）。
- 台帳の YAML エクスポート取得とインポート（置き換え型）もツールとして提供する。

### 検証

- テストを通すこと：読み取り（地図テキストに関係トラバースが含まれること、URL 解決の正確さ）、書き込み（CRUD の往復、検証エラーが REST と同じになること、タグ色の一意性違反が弾かれること）。
- 実際に MCP クライアント相当のリクエスト（HTTP）でツールが呼べることを確認し、その手順と結果を報告書に残すこと。

## 報告
