# 追加ブリーフ20 補足1：MCP 境界を公式 SDK でやり直す（2026-11-22、カイル）

## 背景

追加ブリーフ20の報告では「npm レジストリキャッシュが読み取り専用で通常の npm install ができず、公式 MCP SDK を使えなかった」とされた。しかしユーザーの認識では、この実行環境から外（インターネット）へ出られるはずである。まず事実を検証し、到達可能なら公式 SDK でやり直すこと。

## 手順

### 1. 到達性の検証（最初に必ず実施し、証拠を報告書に残す）

Codex の実行環境の中から、次を実際に実行して結果（成功／失敗とエラー文）を記録する：

- `npm ping`
- `npm view @modelcontextprotocol/sdk version`
- `curl -sI https://registry.npmjs.org/`

到達できない場合は、推測で済ませず、どのコマンドがどのエラーで失敗したかをそのまま報告して止まること（自前実装のまま据え置き、カイル側で環境を確認する）。

### 2. 公式 SDK での再実装（到達できた場合）

- 依存に公式 **`@modelcontextprotocol/sdk`** を追加し、MCP の JSON-RPC／Streamable HTTP 境界（`mcp/protocol.ts` の自前実装）を SDK の実装に置き換える。
- ツールの定義（33ツールの名前・description・スキーマ・挙動）、地図テキスト、REST クライアント、検証の一元化（MCP は REST だけを呼ぶ）は現行のまま維持する。ツール仕様を変えない。
- 起動方法・接続先（`http://<LAN IP>:3333/mcp`、ステートレス Streamable HTTP、認証なし・LAN 限定）は現行のまま。

### 3. 再検証

- 全テスト（MCP 対象テスト＋全体）を再実行し、結果を記録する。
- 実 HTTP メッセージで initialize / tools/list / tools/call（get_network_map）を確認する。
- 可能なら公式 SDK のクライアント側 API で接続確認まで行い、相互運用の証拠とする。

## 報告

- 結果をプロジェクトの `報告書.md` に追記すること（到達性検証の証拠、SDK のバージョン、置き換えた範囲、テスト結果、残課題）。
