# ADDENDUM-24-SUPPLEMENT-1: 関係名ラベルのプレースホルダー対応

ADDENDUM-24 の関係名ラベルをテンプレート化し、関係ごとに値を
差し込めるようにする。例：

- 関係名：終点の名前 =「ポート{}」
- 関係：終点プレースホルダー =「8」
- 表示：「ポート8」

## モデル差分

### 関係名（ADDENDUM-24 の定義エンティティ）

- 始点の名前／終点の名前はテンプレートとして扱う。`{}` が
  プレースホルダー。1つのラベルに `{}` が複数あってもよい
  （すべて同じ値で置換する）。

### 関係（ADDENDUM-24 の3要素に2つ追加）

- 始点プレースホルダー（文字列、任意、既定は空）
- 終点プレースホルダー（文字列、任意、既定は空）

## 表示ルール

- ラベル = テンプレートの `{}` を、その関係の対応する
  プレースホルダー値で置換したもの。
- 値が空なら `{}` は `-` に置換される（「ポート{}」→「ポート-」）。
  スロットがあることは示しつつ、画面が騒がしくならない形にする。
- テンプレートに `{}` がなければ値は使われない。
- テンプレート自体が空なら、ADDENDUM-24 の既定どおり関係名で代替する
  （プレースホルダーは適用しない）。

## 一意性の拡張

- 一意キーを（関係名、始点、終点、始点プレースホルダー、
  終点プレースホルダー）に拡張する。同じペア・同じ関係名でも
  ポートが違えば別の関係として持てる（リンクアグリゲーション等）。

## 各層の差分

- DB：起動時移行の次番号で関係テーブルに2列追加する。
  既存行は空で埋まる。
- YAML：関係に fromPlaceholder / toPlaceholder（空なら省略可）を
  追加する。旧形式の取り込みは値なしとして扱う（既存の1段変換に
  乗せる）。
- REST：関係の入出力に2フィールドを追加。共有検証に寄せる
  （文字列、長さ上限は他の短文フィールドと同程度）。
- MCP：関係の作成・更新ツールに2引数を追加。地図テキストと
  近傍表示のラベルは置換済みの形で出す。
- GUI：関係の追加・編集ダイアログで、選択中の関係名のラベルに
  `{}` が含まれるときだけ、対応するプレースホルダー入力欄を出す。
  関係タブとポータルのラベル表示は置換済みで描画する。

## 検収条件

- 例の再現：終点の名前「ポート{}」＋終点プレースホルダー「8」の
  関係が、ポータルと地図テキストで「ポート8」と表示される。
- 同じペア・同じ関係名でプレースホルダーだけ違う2件が共存でき、
  完全一致の組は拒否される。
- 既存テスト全件パス＋上記の新規テスト。
- README と schema.sql を更新し、結果を 報告書.md に追記する。
