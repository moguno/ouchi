# 追加ブリーフ 17：アイコン参照を generic／favicon／URL の3種に統一（2026-11-21、カイル）

## 背景

追加ブリーフ16でアイコン参照は `preset:`／`generic:`／`dashboard:` の3系統＋ローカルキャッシュになった。しかし `dashboard:` はローカルに保存した SVG ファイルへ依存するため、同じ YAML でも環境のキャッシュ状態で表示が変わり、YAML が安定しない。ユーザー決定により、参照の種別を次の3つに統一する。

## 仕様

### 1. 参照の種別は3つだけ

- **generic**：アプリ同梱の汎用アイコンのキー。既存プリセット9種もここへ統合する（キーはそのまま使えること）。
- **favicon**：そのサービス自身の favicon を使う指定。表示時にサービスの URL（origin）の favicon を指す。取得できない場合は generic の代替アイコンで表示する。
- **url**：アイコン画像の URL をそのまま保持する。表示できない場合は generic の代替アイコンで表示する。

YAML エクスポートでは、この3種がそのまま読み取れる形で往復すること（環境依存のローカルファイルを参照しない）。

### 2. dashboard-icons の扱い

- ローカルキャッシュ方式（適用時に SVG をデータボリュームへ保存する仕組み）は**廃止**する。
- 検索ピッカーは残す。dashboard-icons の候補を選んだら、その CDN URL を **url 種別として保存**する（検索は「URL を見つける手段」という位置づけ）。
- 索引の同梱とオフライン検索は追加ブリーフ16のまま維持する。

### 3. 移行

- 既存データの `preset:<key>` は generic のキーとして読み替える。
- 既存データの `dashboard:<slug>` は、その dashboard-icons アイコンの CDN URL（jsDelivr の svg パス）へ変換して url 種別として読み替える。
- 読み込み／インポート時に正規化し、次回エクスポートでは3種だけが出力されること。

### 4. その他

- 汎用アイコン集の同梱、ピッカーの2グループ表示（汎用／dashboard-icons）は維持する。favicon と URL の直接指定もピッカー（サービス編集）から選べる／入力できること。
- 読み取り専用デモは同梱アセットのみで描画できる現状を維持する（サンプルデータのアイコンは generic に寄せる）。
- 再ビルドし、`成果物/v1/` と `成果物/demo-pages/` に同期する。
