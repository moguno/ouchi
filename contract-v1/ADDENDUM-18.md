# 追加ブリーフ 18：デバイスに petname（愛称）を追加（2026-11-21、カイル）

## 内容

デバイス（ノード）にもサービスと同じ **petname（愛称）** を持てるようにする。ユーザー指示。対象は台帳スキーマ・API・GUI・デモサンプルを含む全体（これはスキーマ変更を伴う機能追加。契約側の DB_SCHEMA_DRAFT はカイルが後で同期する）。

## 仕様

### データ

1. デバイスに `petname`（任意、文字列、空＝未設定）を追加する：
   - DB スキーマ（devices テーブルに petname カラム）。既存 DB 向けに `ALTER TABLE` のマイグレーションも用意すること。
   - API の型・バリデーション（共有型 PortalDataV2 系）に追加。サービス側 petname と同じ扱い（任意・trim・空は未設定）。
   - YAML エクスポート／インポートに含め、往復で保持されること。
2. 管理 UI のデバイス編集ダイアログに「ペットネーム」入力欄を追加する（サービス編集と同じ流儀）。

### 表示（ポータル表示）

3. デバイスカードの **メイン表示は petname**。未設定の場合は hostname にフォールバックする（サービスの表示規則と同じ）。
4. カードの **サブ表示に、IPアドレス／ホスト名／カテゴリ** を出す：
   - IPアドレスは、そのカードが表示されているネットワークでの所属 IP。
   - petname 未設定でメインが hostname の場合は、サブに hostname を重複させない（IP とカテゴリのみでよい）。
5. 管理 UI のデバイス一覧でも petname が分かるようにする（メイン表示に petname、hostname を併記）。

### デモサンプル

6. サンプルデータの全デバイスに、note の内容に沿った短い日本語の petname を付けること（サービスの petname とは重複させない）。付けた petname の一覧を報告書に明記する。

## 検証

- テスト（petname の CRUD、YAML 往復、未設定時のフォールバック表示、サブ表示の重複回避）を通すこと。
- デモを再ビルドして `成果物/demo-pages/` に同期し、`成果物/v1/` も再生成すること。
