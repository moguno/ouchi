# ADDENDUM-26: 設定画面への Base UI 段階導入

## 前提（カイルが準備済み）

- パッケージは **`@base-ui/react` 1.9.0**（安定版）を導入済み。
  package.json / package-lock.json は更新され、node_modules にも
  入っている。追加のインストールは不要（Codex のサンドボックス
  からはレジストリに届かないため、カイルが事前に導入した）。
- 旧名 `@base-ui-components/react` は使わない（rc.0 で止まっている）。

## 目的と範囲

対象は**設定画面（管理画面）だけ**。ポータル側は変更しない。
ファイル肥大と AI 作業時の文脈量を減らすため、定型部品の
「振る舞い」の実装を Base UI に移す。見た目は自前 CSS のまま。

段階導入（この順で）:

1. **ダイアログ**: エンティティ追加・編集ダイアログ、削除確認、
   関係ダイアログの土台（オーバーレイ、フォーカス管理、Esc、
   開閉状態）を Base UI Dialog に移す。
2. **タブ**: 管理画面の5タブを Base UI Tabs に移す
   （キーボード操作はライブラリ標準に従う）。
3. **ポップオーバー的部品とスイッチ**: アイコンピッカーの
   開閉の振る舞い、真偽値スイッチ類（メーター有効、VM フラグ等）
   を Base UI の対応部品に移す。無理に寄せると複雑になる箇所は
   対象外として報告に残す。

## 制約

- 見た目・表示文言・操作の結果は現行と同一に保つ。CSS クラスは
  既存のものを各部品に付け、状態セレクタが data 属性ベースに
  なる場合のみ CSS 側を最小限調整する。
- ネイティブ select で足りている箇所は移行しない。
- 追加の依存パッケージは入れない。
- API・DB・YAML・MCP・サーバー側は変更しない。

## 検収条件

- 既存テスト全件パス（部品の実装詳細に依存するテストの書き換えが
  必要な場合は最小限にし、報告書に明記する）。
- 型チェック・ビルド成功、verify.py ALL OK。
- 移行した部品と、対象外にした部品（理由つき）の一覧、移行前後の
  対象ファイル行数を 報告書.md に記録する。
