# ADDENDUM-28: スタイルシートの分割（リファクタ続編）

ADDENDUM-26（Base UI 導入）の**後**に実施する。新しい構造に
合わせて CSS を切り分ける。

## 現状

- `src/portal/styles.css` が単一ファイル 3,355行（ADDENDUM-26 で
  行数・内容が多少変わっているはずなので、開始時に実測する）。
- クラス名は ouchi-manage／ouchi-relation／ouchi-dialog 等の
  領域接頭辞で統一されている。

## 分割方針

- 接頭辞（領域）単位でファイルを切り分け、ブリーフ25で分けた
  コンポーネント構成に合わせて、各コンポーネント／タブが自分の
  CSS を import する形にする。
- 共通の CSS 変数と土台（リセット、レイアウトの基盤）は
  base.css（仮称）に残し、最初に読み込まれるようにする。
- demo.css は対象外。

## 制約（厳守）

- **ルールの中身とカスケード順序を変えない**。セレクタの書き換え、
  詳細度の変更、プロパティの整理・統合はしない。切り分けて
  移動するだけにする。
- 見た目の同一性が条件。分割前後でポータルと管理画面の主要画面が
  同じに見えること。
- TSX 側の変更は import の付け替えに限る。
