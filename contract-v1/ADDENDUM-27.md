# ADDENDUM-27: デバイス削除時の 500 を 409 に直す（既存バグ修正）

## 現象

所属（membership）を持つデバイスを削除すると、API が 500 を返す。
ブリーフ22の検収時に発見。プロパティ実装前のイメージでも再現する
既存バグ。

## 仕様

製品内の既存パターン（関係名の削除、使用中なら 409）に揃える：

- `DELETE /api/devices/:id`：そのデバイスに所属・サービス・関係の
  いずれかが残っている場合は **409** を返し、本文に blockers
  （memberships / services / relations の件数）を含める。
  子要素が何もないデバイスは従来どおり削除できる（200）。
- 500 になる経路を残さない（外部キー制約の例外を 409 に変換する
  のではなく、事前チェックで判定する）。
- GUI：削除が 409 の場合は既存のエラー表示経路で理由が伝わること
  （新しい画面部品は足さない）。
- MCP の delete_device は REST のエラーをそのまま伝えること
  （追加実装が要る場合のみ最小限）。

## 検収条件

- 再現テスト：所属つきデバイスの削除が 409（blockers つき）に
  なること、子要素なしデバイスの削除が従来どおり成功すること、
  の回帰テストを追加する。
- 既存テスト全件パス、型チェック・ビルド成功、verify.py ALL OK。
- 結果を 報告書.md に追記する。
