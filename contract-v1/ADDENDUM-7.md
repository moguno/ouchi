# 追加ブリーフ 7：GitHub Pages 向けデモ版（YAML モード＋サンプルデータ）（2026-11-21、カイル）

## 背景

ユーザーの発案と決定：台帳エクスポート（YAML）をクライアント側で読ませれば、バックエンドなしで GitHub Pages のような静的ホスティングでもポータルサイトが作れる。ファーストリリースのショーケースとして、**サンプルデータによる表示専用デモ版**を作る。

## 仕様

1. **YAML モード**
   - SPA に、API の代わりに台帳 YAML を読み込む動作モードを追加する（デモ用ビルドとして切り替えられること。通常の API モードの挙動は変えない）。
   - YAML は静的ファイルとして成果物に同梱し、相対パスで fetch する。形式は実装済みのエクスポート形式（`format: ouchi-ledger/1`、自然キー）そのまま。
   - YAML（自然キー）→ ポータル表示モデルへの変換は、API 境界（apiClient）と同等の層に置くこと。
   - YAML モードでは**表示専用**：管理画面の編集系 UI は出さない（デモである旨の小さな表記を入れる）。
2. **サンプルデータ**
   - 実在の自宅データは使わない。サンプル専用の架空データを作る。
   - 作り方：実データのエクスポートを雛形に、値を架空データへ置き換える（形式の厳密な踏襲のため）。
   - IP は TEST-NET（192.0.2.0/24）帯、ホスト名・サービス名は架空のもの。ネットワーク構成は「インターネット／自宅 LAN」の2つ程度、デバイス 5〜7 台、サービス 6〜8 件、関係 3〜4 件、外部 SaaS 1 件を含む、見栄えのする構成にする。
3. **GitHub Pages 対応**
   - 静的アセットと YAML は相対パスで読み込めること（Pages のサブパス配信 `/<repo>/` でも動くように、デモ用ビルドの base は相対にする）。
   - 成果物は `成果物/demo-pages/` に、静的ファイル一式＋サンプル YAML を配置する（そのままリポジトリへ置けば Pages で配信できる形）。
   - GitHub への push と Pages の有効化はユーザーのアカウント操作が必要なので、今回の範囲外。成果物を渡すところまで。
4. **確認**
   - デモ用ビルドが成功すること。
   - 静的ファイルだけでポータルが表示されること（ローカル HTTP サーバー等で確認。サンドボックスの bind 制限で実起動できない場合は、その旨と代替確認の内容を報告する）。
   - API モード（通常ビルド）のテストが従来どおり全件成功すること。
